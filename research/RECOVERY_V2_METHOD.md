# Recovery-v2: source-bound context and provisional semantic review

This is a separate **offline prototype**, not an inference runner. `semantic_recovery_v2.py` reconstructs contexts, builds proposed requests, reads existing reports and writes pending review artifacts. There is no generation, approval, retry-reset, training or dataset-export command. Recovery-v1 code and its original 13 plan-bound hashes are unchanged.

The actual pilot report and HTML have not been supplied in Work. The user reports 20 requests, 20 mechanically accepted fragments and zero remaining. We cannot yet report semantic-error counts, a bilingual verdict for the real outputs, or post-pilot field completion. The source-only audit displays the planned first 20 jobs with Arabic explicitly **unavailable**. It must never be mistaken for an audit of generated candidates.

## Why mechanical acceptance is insufficient

Recovery-v1 separates prose from source-owned mathematics, numbers and reasoning boundaries. A short Arabic word such as `الاستثناء` can pass script checks while conveying exception/exclusion rather than arithmetic subtraction. The reported example is a concern awaiting the actual output, not a verified model-error count. A one-word isolated prompt cannot identify every operation, referent, inflection or geometric sense. Script checks do not prove equivalence; increasing their scope into an automatic semantic approval rule would be unsupported.

The new payload quotes the frozen problem, complete current sentence, previous/next steps and exact target span. It asks for only that original fragment. The model must preserve the English claim even if wrong and must not solve it, add assumptions or emit literal equations/digits. The unchanged Python assembler restores exact source literals. Source hashes and target offsets must agree. A conservative 4,096-byte/token envelope, including the 512 generated-token ceiling and safety margin, blocks oversize contexts rather than silently truncating them. No actual tokenization or model quality is claimed.

The 25-entry `semantic_glossary_v2.json` supplies inflection-sensitive suggestions for arithmetic, comparisons, connectives, geometry and notation. Longer overlapping terms take precedence (`if and only if`, `less than or equal to`, `square root`). Glossary matches and suspect alternatives create **provisional AI risk flags** only. Regional Arabic synonyms, inflections and paraphrases require bilingual judgment. Arabic normalization is analysis-only; recorded text is never normalized in place.

Source-owned errors are separate. The planned circle criterion omits the lower center-distance bound: radii 7 and 1 at distance 5 satisfy the stated upper bound but the circumferences do not intersect. Another source step squares `-2 <= sqrt(k+40)` into `4 <= k+40`; `k=-40` witnesses non-equivalence. Faithful translations must retain those claims. Neither source concern is an observed model translation failure.

## Evidence and human workflow

Report ingestion checks the original approval schema, exact plan/model/digest/20/2/512 limits, counters, hashed outcome bodies, accepted candidates, interruption totals and exact HTML table correspondence. A report omits reservation records, so upload-only validation is explicitly weaker than the laptop audit. The laptop additionally verifies all 814 protected snapshot files, original checkpoint/history reconstruction, immutable consent, reservation ledger, dispatch witnesses and external checkpoint through the unchanged recovery-v1 readers. It checks recorded model identity without contacting Ollama.

Each review item binds the original source record/field/slot, full context, exact candidate and proposed AI risks by SHA256. In-memory completion accounting combines original accepted slots with recorded new slots, assembles full fields through unchanged validators, and counts complete trajectories. It writes no original checkpoint or training dataset.

`human_review.html` is self-contained, has no network access, and shows English context, raw Arabic, separate source warnings and optional correction proposal. Every state starts pending. A reviewer chooses pending/approved/rejected/needs_correction, enters their real identity, category/severity and explicit attestation, then saves a separate JSON. The browser records its actual UTC clock only for non-pending decisions; a proposed correction cannot be silently approved as the original candidate. The interface does not authenticate identity or prove review happened. Preserve the reviewer file locally. `semantic_review_v2.py` can validate and import it into a separate immutable `human_reviews` directory; it grants neither training eligibility nor inference authorization. All corrections need independent review before any future derived corpus.

Run the source-only development audit with `semantic_recovery_v2.py --repo-root <repo> --static-plan <original-plan>`; actual report and HTML may be supplied together. This mode explicitly does not certify the laptop snapshot. The Windows offline launcher under preparation will use the fixed laptop plan and auto-discover the existing report without running the old execution launcher.

## Proposed diagnostic, not approved

The source-risk stratifier selects at most 12 distinct original slots covering subtraction, circles, radii, equivalence, comparisons, interval notation, squaring, digits, between, base and conjunction. It proposes two **new** isolated-versus-context/glossary arms, one request per slot per arm, maximum 24 requests total and 512 generated tokens each. Payload/context/source hashes are bound in `experiment_proposal_NOT_APPROVED.json`. The actual-plan offline check found all 12 strata, but the design and budget remain provisional until actual pilot review and human design review. The old 20 requests stay exhausted. No approval identity or timestamp is created and the proposal cannot pass the old approval validator. A separately reviewed runtime and explicit budget would be needed to execute anything.

Pre-register script/structure compliance per charged request; paired semantic decisions from blinded bilingual review; literal/operation/relation/entity fidelity; correction rate and review time. Report failures and interrupted reservations in the denominator. Pair conditions by source slot and cluster uncertainty by source problem; this deliberately selected small diagnostic sample cannot estimate corpus-wide accuracy. Rate human disagreement and adjudicate without deleting initial decisions. Separate an ordinary translation error from an English-source reasoning error. Results remain unknown.

Terminology references are primary Arabic curriculum usage, not an exhaustive bilingual standard: [Jordan NCCD framework](https://nccd.gov.jo/EBV4.0/Root_Storage/AR/FW/Math_Framework_Arabic.pdf) (indexed text inspected; PDF retrieval timed out) and [Grade 5 workbook](https://nccd.gov.jo/EBV4.0/Root_Storage/AR/Math/2025/G05/2/MT05/WB/MA.05.WB2_2025.pdf). [MathWorld circle intersections](https://mathworld.wolfram.com/Circle-CircleIntersection.html) supports the mathematics, not Arabic translation authority.
