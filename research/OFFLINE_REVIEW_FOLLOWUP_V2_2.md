# Offline follow-up tools — separate from frozen execution

Two additive tools address the preparation handoff and narrow semantic-review gaps without changing any frozen v2.1 file.

`diagnostic_preparation_audit_v2_2.py --repo-root ... --report ... [--blind-review ...]` validates an actually supplied zero-request preparation report and optional source-bound preview. It rejects active budgets, actual outcomes/runtime metadata, identity mismatches, changed limit types and invented preview candidates. The summary explicitly separates the report's required model digest from an observed installation, and the reported local-history flag from a private ledger replay. Without the original blind file it does not invent a checked24-item inventory. It never reads the key or authorizes any request. Originals remain unchanged; separate immutable private output lives in `recovery_artifacts/diagnostic-preparation-audit-v2.2/`. GPT can process supplied files without repeated user terminal commands. The current handoff's actual report bytes are not exposed here, so no private report hash or new laptop proof is published.

`semantic_review_notes_v2_2.assess(context, candidate)` returns the exact frozen v2.1 analysis/raw candidate plus separate AI notes. It explains a compound comparison/conjunction scope false positive and flags narrow numeral-agreement misses after conjunction/preposition clitics. It never suppresses original flags or changes mechanical validation, source labels, prompts, corrections, human states or training eligibility. It is not part of the42-file execution runtime and must not be injected into primary blinded assessment materials.

Tests reconstruct all12 real source contexts, exercise observed sentinels and valid alternatives, distinguish flawed English from Arabic error, retain all24 missing preview observations, and check immutable input/output handling and exact boolean/integer types. A native CLI subprocess denies sockets/operator-key access and preserves a synthetic nine-attempt checkpoint. Synthetic examples are development fixtures, not new generated translations or human decisions. The full shared Windows/Linux suite includes these checks and the existing native Windows package/hash/consent guards.
