Download and double-click the [sync preflight CMD](prm_arabic_english/check_arabicprm_sync_windows_v1.cmd). Use the same checkout path as the restart checker. Allow enough free space for a full copy of ordinary files, including ignored local artifacts. Avoid editing or running Git in that checkout while the scan runs. The wrapper checks its embedded standard-library helper before running it with installed Python. Its exact CRLF bytes and expected SHA256 are recorded in the adjacent [checksum](prm_arabic_english/check_arabicprm_sync_windows_v1.cmd.sha256).

The only writes are to a temporary helper and a new timestamped folder under `%LOCALAPPDATA%\ArabicPRM\sync-preflight-v1`. The console prints the private `report.json` path. The snapshot contains ordinary file bytes, staged index bytes, local refs, reflogs and Git object files as stored; ignored and untracked files are included. The checksum manifest covers the copied bytes, not filesystem ACLs, alternate streams, or external dependencies. Paths bearing the excluded benchmark name are skipped without reading their files; those files stay in the original checkout. Junctions, symbolic links, Git locks, alternate object stores and linked worktrees block a verified snapshot. The tool rejects changed inventories, low space and copy mismatches. An incomplete snapshot is not a verified backup.

Git inspects status in the backup, with external filters disabled. An ignored directory can appear as a single status row; the manifest still lists each backed up file. The Windows fixture covers a hash-like ignored path longer than 260 characters. The helper uses explicit extended paths for ordinary file I/O without changing Windows settings. `possible_path_overlaps` compares normalized file and directory paths against the pinned committed changes. A match is a potential overwrite or collision, not a confirmed content conflict. A non-match does not authorize moving any protected or private file. Unavailable commit ancestry is reported as unknown. Keep the snapshot and report local; they can contain private files, filenames and Git history.

| Report state | Next action |
|---|---|
| `backup_verified_review_required` | Keep the backup and original checkout. Review `changes_by_xy`, `possible_path_overlaps` and `comparison`. If help is needed, share only counts and redacted categories, never the snapshot, raw private report, or protected file contents. |
| `blocked_preserve_checkout` | Keep the original. Read the reason; if Git or an editor is writing files, wait for that activity to finish before repeating. Do not use an incomplete snapshot as a restore source. |

There is no in-place update mode. A fast-forward would change the checkout even without local-only commits, so it is not appropriate while the dirty paths and their purpose are unknown. After reviewing the private result, decide which local changes belong in a separate development checkout, which local artifacts must stay where they are, and whether a new clean checkout of a freshly verified research SHA is appropriate. Do not copy private artifacts into a Git commit or assume a merge would be harmless. Updating or creating an execution checkout is separate from running the diagnostic; the [qualified human design review](DIAGNOSTIC24_HUMAN_DECISION_CHECKLIST_V2_2.md) can proceed independently.
